CTF & RE : ret2win, unpacking, et une suite de 80 crackmes

2026 Root-Me · ELF/PE IDA · gdb+pwndbg · pwntools

Trois angles de reverse : une exploitation binaire propre (ret2win) sur Root-Me, le dé-packing et l'analyse d'un crackme protégé, et un projet à part — un générateur de ~80 crackmes que je résous par script.

01 Root-Me — Stack buffer overflow & ret2win

Challenge app-systeme-ch72 : un PE32 x86 qui lit son entrée avec une fonction de type gets() dans un buffer de 16 octets, sans contrôle de longueur. Objectif : lire un fichier protégé appartenant à un autre utilisateur.

ProtectionÉtat
ASLROFF
DEPOFF
Stack cookie (main)absent

Avec ASLR/DEP off et pas de cookie, c'est un ret2win : il existe une fonction cadeau qui system() un shell. Il suffit d'écraser l'adresse de retour de main par la sienne.

; give_shell @ 0x401000 — la cible ret2win
0x401000  push  0x41b000       ; "C:\Windows\system32\cmd.exe"
0x401005  call  0x403bcc       ; system()
0x40100d  ret

Layout de pile de main : buffer 16 o → counter 4 o → saved EBP 4 o → return address. Le padding est donc de 24 octets avant d'atteindre EIP, qu'on remplace par 0x401000.

# payload
payload = b"A"*24 + p32(0x401000)   # ret → give_shell → cmd.exe

02 Crackme ELF packé UPX

Cible : un ELF 64-bit PIE, strippé et packé UPX 4.2.2 (6,7 Ko → 15 Ko une fois déballé). Le workflow de RE d'un binaire protégé, en condensé :

Triage : file, entropie, sections — l'entropie élevée + les tags UPX! trahissent le packer.
Unpacking : restauration de l'image déballée pour retrouver un binaire analysable statiquement.
Statique : reconstruction de la logique de validation (routine de check, transformations sur l'entrée).
Dynamique : gdb+pwndbg pour confirmer le flux, court-circuiter l'anti-debug, observer la comparaison finale.
Solve : inverser la transformation pour reconstruire l'entrée acceptée.

La même démarche que sur un échantillon suspect : identifier la protection, la retirer, isoler la logique utile, prouver le comportement.

03 Projet : un générateur de ~80 crackmes

Pour m'entraîner (et entraîner d'autres), j'ai écrit un générateur qui produit ~80 crackmes répartis en tiers de difficulté, chacun accompagné d'un solveur scripté. C'est autant un exercice de RE que de construction d'outils.
